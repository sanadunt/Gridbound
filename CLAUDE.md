# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project

Gridbound: Ashes of the Bell (v0.4) — an offline-first, pixel-art tactical RPG for the browser. TypeScript + Vite + Phaser 3 (+ GSAP for UI tweens). No backend: the build is a static bundle; `server.js` is only a minimal static file server for Node-based hosts. Node 22.12+ for development.

## Commands

```sh
npm ci
npm run dev                         # Vite dev server on 127.0.0.1
npm test                            # all unit tests (node:test via tsx): tests/*.test.ts
node --import tsx --test tests/combat.test.ts                         # one test file
node --import tsx --test --test-name-pattern="shield absorbs" tests/combat.test.ts   # one test
npm run build                       # tsc --noEmit (typecheck) + vite build -> dist/
npm run database                    # regenerate data/database.json from src/game definitions
npm run docs                        # database + regenerate Gridbound_GDD_GRID_RAID.md
npm run balance                     # play the campaign with scripted expert/casual/novice/idle players (writes artifacts/balance.json)
npm run calibrate                   # re-fit CHAPTER_HP/CHAPTER_DMG to the casual + novice players (prints tables; VERIFY=1 only measures)
DUNGEON=1 npm run calibrate         # re-fit the Undercroft's DEPTH_DMG (prints the table for dungeon.ts)
npm run power-curve                 # casual party power per chapter start (RECOMMENDED_POWER) + Heroic run (HEROIC_POWER_FACTOR)
```

There is no linter/formatter configured; `tsc` (strict) via `npm run build` is the type check.

CI (`.github/workflows/ci.yml`) runs: `npm test`, `npm run database` then **`git diff --exit-code -- data/database.json`**, `npm run build`, `npm run balance`, and `scripts/package-hostinger.py`. So any change to content definitions in `src/game/` (skills, jobs, gear, talents, quests, enemies, campaign, boons) must be followed by `npm run database` and committing the regenerated `data/database.json`. `npm run balance` fails CI unless the expert and casual scripted players (casual may retry a chapter once) clear all chapters, a novice (input every 1.5 s, 30% dodge/Guard, on the casual player's chapter-start profile) clears at least 70% of chapters with one retry, the expert wins every raid it tries, and an idle player cannot clear Act I (neither from a fresh profile nor, chapter by chapter, on the casual player's chapter-start party: `idleChapter`) — so combat/number changes can fail CI there. The scripted players shop and deploy like real ones (harness v2 in `scripts/balance.ts`, shared by `calibrate.ts`/`power-curve.ts`): `shop(p, run)` promotes first and equips the job skill as the stance (a non-healing job skill never replaces the last healer's heal), tier-2 branches rotate per run (`branchOf`; the expert is `RUNS.expert`, the casual/novice `RUNS.casual`, so both branches of every class are fielded), `coverageParty` deploys one hero per class before doubles, and the formation is by role (warriors/monks in front, so they take the claw); in `play()` a dodging hero goes to the nearest free unmarked tile (`safeTile`) and walks back to its formation tile once the mark has landed. Break uptime, ultimates/min, taps/s, dodges, minion hits, per-job DPS/HPS, the novice's per-chapter win rate, the idle player's result per chapter on the casual party (Act III still has an idle win), Undercroft wipe rate/guardian entry HP per depth and Roguelike floors 1-9 are reported (informational) in `artifacts/balance.json`. Raids in the harness are built exactly like `main.ts` `boot()` (`raidBattle`: whole roster + story loadouts + `defaultRaidBuild` + an authored contract, floor = cleared + 1): every enemy at Bronze, every archetype at Silver/Gold, each certified pact combo, a 6-hero party, and Bronze raids after chapters 2/6/10 (casual win rate is informational). Hero growth comes from levels (`LEVEL_POWER`/`LEVEL_HP` in `levels.ts`), gear, talents and jobs; `profileModifiers` is neutral. Enemy strength per chapter is `CHAPTER_HP`/`CHAPTER_DMG` in `simulation.ts` (raids reuse the chapter curve, scaled by `RAID_HP`/`RAID_DMG`, `RAID_PARTY_DMG` for parties smaller than the story cap, and `RAID_TIER_SCALE` per contract tier); after changing hero or enemy numbers, run `npm run calibrate` (≈5 min), paste the tables it prints as they are (the casual margin is built in: at most one loss in twelve runs, median end HP ≥ 50%, then −5% damage; the novice target is ~50% wins at chapter 1 rising to ~60% at 16; damage stays at or above each chapter's idle floor, the least damage at which an idle player loses it on both branch mixes, unless idle wins even at the casual cap; from chapter 6 on each chapter's damage is within ±20% of the previous one (chapters 2–5 may rise further, never fall more than 20%), boss HP never falls, HP ≤ ±20% inside an act — `tests/scaling.test.ts` checks the shape), then `npm run power-curve` (paste `RECOMMENDED_POWER`, a running max so it never falls, and `HEROIC_POWER_FACTOR`), `DUNGEON=1 npm run calibrate` if the Undercroft should follow, and re-run `npm run balance`.

Browser tests (`scripts/*-browser.mjs`, `*-smoke.mjs`) drive headless Chrome over raw CDP via `scripts/browser-harness.mjs` (not Playwright). They expect a dev server on port 5180 and a Chrome binary:

```sh
npm run dev -- --port 5180 --strictPort
CHROME_PATH=/opt/pw-browsers/chromium-1194/chrome-linux/chrome npm run test:browser      # or a single script: node scripts/combat-hud-browser.mjs
npm run test:production    # serves dist/ under a nested subpath
npm run test:webapp        # production build through server.js
```

The harness defaults `CHROME_PATH` to the macOS Chrome path (and adds `--no-sandbox` when running as root); `GRIDBOUND_URL` overrides the dev URL. Navigate in tests with `click.nav('party' | 'campaign' | 'raid' | 'more' | …)`, which goes through the real UI (town buildings, MENU, gate mode tabs) — there is no bottom nav bar. The HUD ◀ (`#home`) walks back one route at a time (MENU → Quests → ◀ is MENU), so `click.nav('camp')` presses it until the camp; on the camp it opens the MENU (the Title screen is MENU → Title). The Undercroft, Raids and Bell Trials open with chapters 1/2/4, so a test that opens them must seed a save that reached them (`seedSave(send)` / `ACT_TWO_SAVE` from the harness, called before `Page.navigate`, or its own `cleared` chapters). `town-ux-browser` covers Continue story, locked modes and the unlock card, the route stack, the Quest Board/Claim all, the Bestiary silhouettes, badges, per-hero sprites, the coached first battle (forced with `window.gridbound.coach(true)`; the unlock card with `window.gridbound.unlockIntro()`) and the defeat/victory screens at 390×844 and 1280×900. Screenshots go to `artifacts/` (gitignored). `language-browser` and `story-scene-browser` cover the language switch and story scenes (narrator nameplate, camp scenes and story choices, the Journal epilogue in EN/ID, the finale); `save-safety-browser` covers the boot migration/backup, the guarded New Commander, backup export/import, quiet town saves and the no-IndexedDB fallback; `raid-setup-browser` covers the raid setup (hero picker, party size, locked quarries, pacts), the Bell Tonic and the relics. Every session has a Commander, so town navigation (`navigateTown`) flushes the pending save before it renders: wait for the route (`.town-game-shell[data-town-route]`) or its controls after a navigation click instead of reading the DOM immediately. Not every browser script is in `test:browser`; others (e.g. `d2`…`d7`, `pact`, `training`, `archives`) are run individually (`d3`/`d4`/`d6` start their own Vite server on 5183/5185/5186, overridable with `D3_PORT`/`D4_PORT`/`D6_PORT`; `d7` and `currency-ui` read `GRIDBOUND_URL`).

## Architecture

- **Pure game logic in `src/game/`, no DOM.** Everything here is importable from Node tests and scripts. `simulation.ts` holds the `Battle` class: a seeded, deterministic, fixed-timestep combat simulation (`tick(dt)`, `tap`, `move`, `act`, `potion`, `ultimate`, `snapshot()`), parameterized by mode (`adventure`/`raid`/`endless`…) and `BattleOptions` (roster, loadouts, boons, rogue/raid builds, raid contracts). Tests advance it with `b.tick(1/60)` loops; determinism (`seeded encounter behavior is reproducible`) is a tested invariant — don't introduce `Math.random`/wall-clock into it. Combat rules: only casts outside `SUPPORT_KINDS` are offensive (precision, echoes, Second Thunder and leech count `offensiveActs`); delay/stun/Frost/job intent delay go through `delayIntent`, a per-intent-cycle budget (`CONTROL_MIN`/`CONTROL_SHARE`, reset in `telegraph()`); overlapping regen/Battle Hymn keep the stronger effect; curses are per hexer (`curses`, exposed in `snapshot()`); `heal(target, amount, source)` takes the healer so the healer's perk applies; nobody is downed once the boss has fallen (a counter/thorn kill on the hit that would down the last hero leaves that hero at 1 HP), and a same-frame boss death beats a wipe. Party tools are scale-invariant: a potion heals `POTION_HEAL` (28%) of each hero's max HP, Ninefold Dawn deals `ULT_BASE` + `ULT_DAMAGE` × boss max HP and heals/shields `ULT_HEAL`/`ULT_SHIELD` of max HP, Mending Light's party heal is 20 × `skillPower`, and resolve from damage is a share of `resolveRef` (the chapter's final-boss HP in Story/Undercroft, the boss itself in raids/Roguelike; `RESOLVE_DEALT`/`RESOLVE_MINION`) or of the party's total max HP (`RESOLVE_TAKEN`). Late fights keep their threats: `staggerThreshold()` is `STAGGER_SHARE` of the boss's max HP capped by `STAGGER_CAP` × `STAGGER_CAP_GROWTH`^(chapter−1), a break lasts `BREAK_SECONDS`, and minions strike `MINION_FIRST` s after spawning with `MINION_HP` × the chapter boss's HP. The story party is capped at 8 (`storyPartyCap`), so one tile is always free; Roguelike floors 1–`ENDLESS_EARLY_FLOORS` hit `ENDLESS_EARLY_DMG` harder (fading over the next three floors).
- **Content definitions** are plain TS data: `content.ts` (`KITS` basic jobs/skills, `ROSTER`), `jobs.ts` (advanced/third jobs, `GEAR`, sets), `talents.ts`, `levels.ts`, `quests.ts`, `world.ts` (`CAMPAIGN`, `ENEMIES`, `BOONS`), `story.ts`/`narrative.ts`/`characters.ts`, `d8-content.ts`. Every stage has a `beat` (the pre-wave story line); a beat that names an enemy must name that stage's archetype (`tests/story-beats.test.ts`, EN names and nicknames like 'Cantor'/'scavengers') — rewrite beats, never reorder enemy lists. `StageDef.enemyName`/`enemyTitle` rename a stage's enemy (Vharok's ally chapters 8/12/16 show what rides him) and `prepareStage` uses them; `variantName` builds 'Ashbound Last Watch' (no 'The', no double Frost). `STORY_CHOICES` (`narrative.ts`) open once chapters 0..chapter−1 are cleared (`choiceOpen`/`pendingChoices`); a choice's `line` is a sentence of the final outro that an option's `line` replaces (`storyOutro`, used by the result screen, Journal and finale); `epilogue()` returns only the choice outcomes (the lead line is the UI key `journal.epilogue.lead`); `CHARACTERS[id].fateLine` is each hero's finale line. `data/database.json` and `Gridbound_GDD_GRID_RAID.md` are generated exports of these — never hand-edit them. Tier-3 job perks are data too (`Job.perk` in `jobs.ts`: `barrier`/`echo`/`intentDelay`/`castLeech`/`minionHeal`/`overhealBarrier`) read by `Battle` — don't key combat rules on job ids; `tests/job-perks.test.ts` checks that every tier-3 perk fires and that job and AoE skill texts state the runtime numbers.
- **Two save layers:**
  - Legacy `Profile` (`profile.ts`, `save.ts`) in `localStorage` key `gridbound.v3`, with v1/v2 migration; malformed saves disable writes instead of overwriting. Progression mutations (`promote`, `equipGear`, `buyTalent`, `settleProgress`, `completeZone`, `claimQuest`, …) are functions over a `Profile`. `gridbound.v3` is now only the migration source: at boot `ensureCommander()` (main.ts) activates the latest Commander or, when there is none and the legacy save is writable, runs `backupLegacy` (raw copy to `gridbound.v3.backup-<ISO>`, newest 3 kept) and creates a Commander from the live profile (`migrateLegacy`/`adoptCommander`, bank included; the list→create step runs under the Web Lock `gridbound.commander-migration`, so tabs that boot together migrate once). A corrupt/blocked legacy save is not migrated at boot, but Save → 'Continue my progress' (`migrateLegacy(name, true)`) still moves the live profile into a Commander without writing `gridbound.v3`; creating/importing a Commander keeps a 'Saving…' dialog up until the new file is active (`creatingCommander`). `persist()` never writes `gridbound.v3` while a persistent (IndexedDB) Commander exists; with the in-memory fallback it mirrors the Story profile plus bank there (`mirrorLegacy`), and with no Commander at all it writes the live profile. The Phaser engine (whose first frame builds every procedural texture in one ~5 s long task) is started only after that boot step settles (`startEngine`; a 6 s fallback covers a lookup that never answers — starting earlier would let the long first frame hold back a merely slow lookup; separately, if the Commander lookup has not answered after 1.5 s, the raw legacy save is backed up and `persist()` writes the live profile to `gridbound.v3` until a Commander activates, so a stalled IndexedDB never leaves progress only in RAM), and the dev hook `window.gridbound` appears at the same moment, so tests never race the migration. Browser tests that seed `gridbound.v3` after a first boot must also delete the `gridbound.commanders.r1` IndexedDB (see `dungeon-browser.mjs`), or the existing Commander wins. Backups ('Download save backup') are importable from Save → Import save: a Commander document, a `gridbound-recovery` file or a `{kind:'gridbound-legacy',version:3,profile}` envelope (`commanderFromBackup` in `save.ts`).
  - **Commander** system (`commander.ts`, `commander-session.ts`): IndexedDB (`gridbound.commanders.r1`) documents holding per-mode state for `story | roguelike | raid`, slots (`manual-1..3`, `auto`), and run checkpoints saved at encounter boundaries. `CommanderSession` serializes writes, checks revisions, and goes read-only when another tab commits (`StaleCommanderError`); `dirty` means a save is queued/in flight or failed, `failed` only the latter (the status bar warns only on `failed`/stale). `persist()` skips the commit when the revision and serialized context equal the last successful save, so re-rendering the town does not create revisions; pass an `edit` callback to force a save (and to get past `pendingSettlement`, as result screens do). `materializeProfile(document, mode)` turns a Commander document into the `Profile` the rest of the game uses; `applyRuntimeToDocument` writes runtime state back. Raid/Roguelike profiles are always built from the Story `auto` slot (gold zeroed, Crystal/unlocks from `document.shared`) and a challenge save only raises that slot's hero XP (`mergeChallengeXp`) — manual Story slots are frozen snapshots written only by an explicit save. Ledger, wins and settlement receipts are account-wide: every mode merges them into `document.shared` with `mergeLedger` (per-key max, receipt union) and every mode reads the merge; `document.shared.bestFloor` keeps the deepest Roguelike floor once (`bestFloorOf` also reads rogue slots for older documents), so loading an older rogue preset never lowers it and Story descent quests read it. Every `StoredStoryState` key must survive `normalizeStoryState` (runs on every `list()`/commit) — `tests/commander.test.ts` round-trips a fully populated Profile and fails when a field is dropped. The camp tab is always Story mode (`modeForTownTab`); the HUD wallet shows Story gold and bank Crystal in every mode. Falls back to in-memory session storage if IndexedDB is unavailable.
- **Story progression systems:** `power.ts` (party power vs `RECOMMENDED_POWER` per chapter, refreshed with `npm run power-curve` after balance changes; `heroPower` reads the stance skill — `castValue` per second with job effects, support kinds valued per party size, against the class's first skill at `REF_PARTY` 3 heroes so a hero never rates lower in a bigger party — and effective HP; an attack job skill rates above the basic one, a control/support job skill only by what it gives the party), `journey.ts` (`Profile.journey`: chapter stars — clear / all standing / boss under `STAR_PAR_SECONDS` — star chests, Heroic first clears, deepest Undercroft depth, the active dungeon run, and the camp scenes a first clear owes: `pendingRecruitScenes` hero ids and `pendingChapterScenes` chapters with a story choice or the finale, queued by `completeZone`, omitted when empty, drained by `playCampScenes` in main.ts), `dungeon.ts` (the Undercroft: seeded 7-row room maps per depth, rooms battle/elite/event/treasure/camp/guardian, carried HP/potions/blessings, a pouch that is banked on extract or guardian clear and lost on a wipe; room HP is the unlock chapter's curve × `DUNGEON_HP`, room damage is the depth's own `DEPTH_DMG` (absolute, CHAPTER_DMG units, non-decreasing with depth — `BattleOptions.dungeon.damage` replaces the chapter table) × `FIGHT_DMG[kind]` (a guardian hits harder than a battle room, softer than an elite), guardians carry `GUARDIAN_HP` × the boss stage HP, a saved run keeps at most `STORY_PARTY_MAX` heroes (`normalizeRun`), the camp rests `CAMP_REST` 25%). Maps are versioned (`run.layout`, `MAP_VERSION`; `generateMap(depth, seed, layout)` keeps layout 1 byte-identical so older saved runs keep their rooms) — change the generator only behind a new layout. The run's party is locked while the run is active (`storyPartyLocked`; `setStoryParty` refuses) and every fight is built by `dungeonBattleOptions(profile, run)` from `run.party`, never the current story party; `resolveFight` only updates heroes present in the result. `begin()` marks `run.pendingFight.started` and saves it; while it runs, `frame()` notes the fight's state (`noteFight` → `pendingFight.seen`: HP ratios and potions) and saves on every fall, potion and every 10 s of battle time. Leaving a started fight goes through the flee modal (`fleeFight`: wounds/potions kept, half the pouch lost, the fight waits; the in-battle retreat buttons read 'Flee the room') and a started fight found when the Undercroft route opens (`settleInterruptedFight` in `showTown('dungeon')`, not at boot, so a second tab never flees the first tab's fight) or at Fight resolves via `interruptFight` (a flee at the worse of the noted state and pre-fight HP − `INTERRUPT_WOUND`). Unaffordable event choices are refused without using the event (`choiceNeed`/`EVENT_COST`); lore choices return a letter id from `DUNGEON_LETTERS` (text `dungeon.letter.<id>` in en/id). Dungeon fights are `Battle` mode `'dungeon'` with `BattleOptions.dungeon`; Heroic replays are `adventure` with `heroic: true` (`HEROIC_*` in `simulation.ts`; `heroicScale(chapter)` applies the per-act `HEROIC_ACT` easing — Act IV gets 55% of the bonus — and the dossier text reads it). Gear refinement (`refineGear`, `REFINE_STEP`/`MAX_REFINE`) spends dungeon materials. `completeZone` deploys new recruits into free party slots (cap computed after the clear), then fills remaining slots with benched heroes in roster order; heroes that need a tile get one by role (`roleTiles`/`placeParty` in `story-party.ts`: warrior/monk front, others back then middle). Only deployed heroes have unique tiles (`moveFormation` swaps two deployed heroes, a benched hero's preferred tile may be shared and never displaces anyone; `setStoryParty` lets already-deployed heroes keep their tiles): `normalizeProfile` keeps every valid saved tile and then runs `placeParty` over `storyActive`, so a formation survives reloads and Commander re-materialization; recruits a save predates join at the saved heroes' median level. Chapter gold is `chapterReward` (full on the first clear, `REPLAY_GOLD` 30% on a Normal replay, 0 on Heroic, read before the clear is recorded) and adventure XP is scaled by `replayFactor` (full up to the latest cleared chapter, −15% per chapter behind, min 25%); the result screen shows the gold/Crystal actually credited (`resultReward` in main.ts; a Roguelike act clear shows its bank Crystal on the boon draft) and names recruits who landed on the bench. Heroic has its own recommendation (`recommendedHeroicPower`, `HEROIC_POWER_FACTOR`), the toggle resets when another chapter is selected (`selectZone`), Retry keeps Heroic, and after a defeat in battle 2+ 'Retry this battle' resumes the stage-start encounter checkpoint (`stageStart`, captured in `begin()`, via `resumeEncounter`) with the HP/potions it began with. The journey is stored in the Commander story slot (`StoredStoryState.journey`). UI: `ui/dungeon.ts` (Undercroft route, reached from the Bell Tower/`dungeon` facility), stars/power/Heroic on `ui/world-map.ts`, the camp's next-step guide (`nextObjective` in `ui/town.ts`), styles in `styles/dungeon.css`; covered by `tests/journey.test.ts`, `tests/dungeon.test.ts` and `scripts/dungeon-browser.mjs`; party fill/placement/formation and replay rewards by `tests/story-party.test.ts`/`tests/profile.test.ts`, the guide, skill book, gear inspector, dossier payouts and credited results by `scripts/party-rewards-browser.mjs`, Heroic retries by `scripts/ceremony-browser.mjs`.
- **Mode-specific builds:** `story-party.ts`, `roguelike-build.ts`, `raid-build.ts` produce/normalize the party inputs for `Battle`; `src/economy/` holds currency and the challenge run-wallet/shop/raid-contract logic. Raid slots (`RaidBuild`: unique recruited hero, any of the 9 basic classes, unique tile; `setRaidHero`/`setRaidJob`; `setRaidPartySize` keeps the existing picks and puts added heroes on a free tile; the default party `defaultRaidBuild` is the Story party first) start from the hero's Story loadout in `Battle.reset` — xp, gear, refine and talents carry; job and skills only when the slot keeps the hero's own class. Quarries open via `raidQuarryUnlocked` (ledger kill, first chapter cleared, or an open hunt quest); the UI shows others as locked '???' tiles and `showTown('raid')` falls back to an open one. Only `IMPLEMENTED_RAID_MODIFIERS` (RM01 barrier −25% in `shield()`, RM02 one potion, RM03 aftershock after each all-grid impact, RM05 summon on phase change) can be ticked (at most three) and certified; RM04/06/07/08 are shown as not yet available, and an uncertified combo still plays its pacts as practice (`sandboxRaidContract`). `boot()` normalizes the raid build (falling back to the default party) and constructs the `Battle` before leaving town. Crystal sinks: relics in `BANK_SHOP` are read where Roguelike floors boot (`BattleOptions.relics`: Ward = +1 potion and 15% opening barrier every floor; Fate = `boonDraftSize` 4 cards), and the consumable Bell Tonic is ticked in the Raid/Roguelike setup and paid at departure, only after the `Battle` was built (`BattleOptions.extraPotions`, then `buyBellTonic`). A promoted Roguelike recruit opens each floor on its job skill.
- **Rendering/UI:** `src/render/BattleScene.ts` is the Phaser scene that renders a `Battle` (3×3 hero grid via `ARENA`/`cell`), consuming `battle.events`. Sprites and item icons are procedural (`src/art/`, `items.ts` for equipment icons), audio is synthesized Web Audio (`src/audio/sound.ts`) — no asset files or CDNs; keep runtime fully local/offline. In battle, each hero's grid cell (`#unit-layer .unit-card`) carries a name tag, its HP bar and a skill chip (`[data-skill-switch]`: toggles 2-skill heroes, opens `#skill-picker` for more; its transparent `::before` makes a 36–40px phone tap target that never covers the card's middle and reaches into the top strip of the card below, so cards stack upper rows on top via `--row`; chip taps within 300 ms of a tap on that hero are ignored and a switch shows `#skill-toast`); `#focus-bar` summarizes the selected hero, and the full party list lives in the Status view. `.arena-intel` (boss status chips `#boss-status` — Mark/Weaken/Curse, the last stun's DELAYED/RESISTED note and the enrage countdown — plus the always-visible `#intent` panel) sits in `.arena-slot` above the bottom-aligned arena, overlaying its top where there is no spare height; `#banner` is a thin click-through band in the boss area that `placeBanner()` (every frame while visible) keeps below the intel band and above the front row; counter texts drop their '(G)' under `(pointer: coarse)`; the ready window (`#start-overlay`) is a top sheet that leaves the grid draggable. Readability events from `Battle`: `stun` (DELAYED +Ns / RESISTED; `break` is only a real armour break), `interrupt`, `enrage` (warn at `ENRAGE_WARN`, on at `ENRAGE_AT`), `buff` with text for status casts, `down`/`impact` carrying their cause (`kind`/`name`/`hit`), and banners tagged `kind:'stage'|'potion'`; the scene dispatches `battle-banner` (banner + log) and `battle-log` (impacts and stuns, log-only plus the stun chip) window events that main.ts turns into the banner and the 30-line log. Crit/shake/hit-stop rules live in the Phaser-free `src/render/hit-feedback.ts` (relative crits, per-second shake budget). The Guard button gets `.ready-window` + GUARD NOW while an all-grid hit is within `GUARD_DURATION` (minus a 0.05 s margin: `guardLeft` ticks down before the impact resolves). `src/main.ts` is the large orchestrator: title screen, battle HUD, dialogs, result ceremony (`ui/result-gate.ts`), and Commander session wiring. `ui/town.ts` renders every town route: the camp is a full-screen pixel village (`src/art/town-scene.ts` exports the canvas plus `TOWN_HOTSPOTS` percent rectangles that become `.town-spot` buttons with `data-facility`/`data-open-action`), and the MENU route (`more`) is the JRPG main menu (commands first on phones, the party as a portrait row). Each sign shows the building and, under it, the destination's one name — the same string as its HUD title (`routeTitle`), MENU entry and gate tab ('Gate · Story', 'Old Well · Bell Trials', 'Merchant · Crystal Exchange'; the `endless` mode is 'Bell Trials'/'Ujian Lonceng' everywhere); long HUD titles (`data-long`) switch to the text font so they never truncate. `.town-map` is a size container: sign text scales with the map (`cqw`), and on a narrow map (< 300px wide: small phones, a tall guide) each sign drops to its first line (building name, padlock, a compact badge; the destination stays in the button's `aria-label`), so the nine signs never overlap (`town-screen-browser` checks the sign rects at 360/375/390 px wide, fresh and Act II saves, EN and ID). Staged unlocks are a UI-side table (`ui/unlocks.ts`: `UNLOCKS` dungeon 1 / raid 2 / endless 4 chapters, `featureOpen` also true for a save that already used the mode or whose Commander has a run in it — `noteModesInUse(commander.document)` before every route check): locked hotspots (`data-locked`) and gate tabs show a padlock and 'Clear Chapter n', `showTown`/`navigateTown` refuse a locked route with a notice, the camp plays a one-time intro card (`unlockIntro`, after the camp scenes, skipped under automation) and shows NEW until the mode is visited (per-viewer flags in `localStorage['gridbound.ui.unlocks']`). The HUD ◀ uses `ui/route-stack.ts` (`pushRoute`/`backRoute`: the camp is the root, a gate tab replaces every gate route on top — map → dossier → Raids leaves Raids — the dossier is a step below the map). Badges (`ui/badges.ts`): Training Hall = deployed heroes with a learnable talent, an affordable job or a better affordable gear piece (`heroNeeds`, also a dot in the Party roster), Bell Tower = a new depth or a waiting run, the HUD MENU button (`data-badge`) = ready quests + star chests. The camp guide window never shrinks (the map scales into the rest via container units) and carries 'Next: CH n · name' (`data-continue-story`), one tap to that chapter's dossier. The Quest Board (`ui/quests.ts`) is one list grouped ready → tracked → open → locked → claimed with 'Claim all (n)' (`claimAllQuests`); the Bestiary is a grid of the 18 enemy families, '???' silhouettes until the account ledger met them, with a detail sheet and T1–T4 variant chips (`bestiaryPick`). Heroes who share a class have their own accents (`HERO_LOOKS` in `art/pixels.ts`; `heroKey(classId, heroId)` names the texture/portrait, so `portrait(classId, frame, heroId)` and BattleScene's lazily added hero textures are cached by look; Roguelike recruits use the class sprite). On phones (≤480px) the whole Party route scrolls under a sticky one-line hero header (`.party-sticky`) and a talent tap scrolls its inspector into view. Results keep `.ceremony-actions` sticky at the bottom, show party EXP as a portrait grid with the bench in one line (`xpSummary` in `ui/result-help.ts`), and a Story defeat shows power vs the recommendation, the first hero to fall (`firstFall`, from the `down` events) with its cause, 'How to beat {enemy}' (the counter of the enemy that won) and up to two one-tap fixes (`defeatFixes`: Undercroft when under-powered, talents/job, gear). The first-battle coach (`ui/coach.ts`, `coachFrame` in main.ts) runs in Chapter 1 until it is cleared: each tip once (tap a hero, drag off the first ground telegraph on a hero — `BattleScene.timeScale` 0.3 slows the fight to 30% of wall-clock speed meanwhile: each frame feeds dt × timeScale into the fixed 1/60 s tick loop, so determinism is unchanged — Guard in the GUARD NOW window, the ultimate at 100 Resolve), with Skip and Config → Battle tips (flags in `localStorage['gridbound.coach']`). `ui/world-map.ts` draws the per-act overworld (`src/art/overworld.ts`). `ui/dialogue.ts` plays story scenes (title card + typewriter message pages; a page with `choices` waits for a pick and resolves `playDialogue` with its value — the `safeChoice` (default the last, 'Decide later') gets the focus, a key with no choice focused only moves the focus there and picks within `CHOICE_INPUT_DELAY_MS` of the choices appearing are ignored, so mashing Enter never answers — a `card` page is a closing title card); first-time chapter departures play the chapter intro (narration under the CHRONICLE nameplate, the speaker and portrait only on quoted pages; skipped under `navigator.webdriver`, like the title screen — tests trigger it with `window.gridbound.chapterIntro(i)`). Opening the camp (`showTown('camp')`, or leaving the title screen) runs `playCampScenes`: each queued join scene (`CHARACTERS[id].joinLine`), then the story choice the chapter opened (options + 'Decide later', which leaves it open; the camp guide then points to the Journal), then after chapter 16 the finale (`endingScene`: outro, fate lines, epilogue, Emberhollow card); each is dropped from the journey and saved once played, so Retry/reload never loses it (never before the boot step settles (`commanderChecked`) or over the title screen — `enterEmberhollow` starts them; skipped under automation; `window.gridbound.campScenes()`, `recruitScene(id)`, `endingScene()`). The Journal replays intros, join scenes and the finale.
- **Styles** live in `src/styles/` (`base.css` tokens/windows/buttons/menus, then `title`, `town`, `screens`, `battle`, `result`), imported from `main.ts`. The UI chrome uses the original Gridbound palette (deep forest-green `.win` panels with thin frames, brass-gold `.btn.primary`, outlined `.btn`), `.menu-list > .menu-item` with the ▶ cursor, `.tabs`, `.gauge`; game art (sprites, town, overworld) stays pixel art. Fonts are local `@fontsource` packages (Space Grotesk body, Press Start 2P headings/numbers). The game is one portrait column (`--col`) on every screen size; the battle arena keeps its 600×760 aspect via a size container (`.arena-slot`).
- **i18n:** `src/i18n/index.ts` exposes `t(key, vars)`, `lang()`, `setLang()`; UI strings live in `en.ts` / `id.ts` (`id.ts` is typed `Record<keyof typeof EN, string>`, so `tsc` fails if a key is missing). Language is stored in `localStorage['gridbound.lang']` (default from `navigator.language`) and applied by reloading the page. Game content is localized in place at startup by `localizeContent(lang)` (`src/i18n/content.ts` + `content-text.ts`, keyed by content paths) so `src/game/` sources and `data/database.json` stay untouched; runtime battle strings go through `eventText()`, and validation/storage messages from game modules through `gameText()`. When you add or change player-visible text in `src/game/`, add/update its `CONTENT_TEXT` entry — nothing fails automatically if a hand-written entry goes stale.
- **Dev QA hook:** in dev builds only, `main.ts` exposes `window.gridbound` (`snapshot`, `profile`, `battle`, `step(seconds)`, `boot`, `showTitle`, …). Browser tests depend on it; production smoke tests assert it is absent. Browser tests seed state by pre-writing `localStorage['gridbound.v3']`.
- **Static hosting:** `vite.config.ts` uses `base: './'` so `dist/` works from any subpath; Phaser is split into an `engine` chunk. `scripts/package-hostinger.py` builds a Hostinger ZIP with `.htaccess`; `tests/hosting.test.ts`, `web-deploy.test.ts`, `node-hosting.test.ts` cover deploy config and `server.js`.

## Conventions

- Match the existing dense style: much of `src/game/` and the tests are compact one-line functions/tests with minimal whitespace. Imports use extensionless relative paths.
- Never hard-code player-visible strings in UI code; add a key to both `en.ts` and `id.ts`. Source strings authored inside `src/game/` are mostly Indonesian prose with English names; their translations live in `src/i18n/content-text.ts`.
