# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project

Gridbound: Ashes of the Bell (v0.4) — an offline-first, pixel-art tactical RPG for the browser. TypeScript + Vite + Phaser 3 (UI entrances use the Web Animations API). No backend: the build is a static bundle; `server.js` is only a minimal static file server for Node-based hosts. Node 22.12+ for development.

## Commands

```sh
npm ci
npm run dev                         # Vite dev server on 127.0.0.1
npm test                            # all unit tests (node:test via tsx): tests/*.test.ts
node --import tsx --test tests/combat.test.ts                         # one test file
node --import tsx --test --test-name-pattern="shield absorbs" tests/combat.test.ts   # one test
npm run build                       # tsc --noEmit (typecheck) + vite build -> dist/
npm run database                    # regenerate data/database.json from src/game definitions
npm run docs                        # database + regenerate Gridbound_GDD_GRID_RAID.md
npm run balance                     # play the campaign with scripted expert/casual/novice/idle players (writes artifacts/balance.json)
npm run calibrate                   # re-fit CHAPTER_HP/CHAPTER_DMG to the casual + novice players (prints tables; VERIFY=1 only measures)
DUNGEON=1 npm run calibrate         # re-fit the Undercroft's DEPTH_DMG (prints the table for dungeon.ts)
npm run power-curve                 # casual party power per chapter start (RECOMMENDED_POWER) + Heroic run (HEROIC_POWER_FACTOR)
npm run package:itch                # tsc + `vite build --mode itch --outDir dist-itch` (no manifest/app icons/Home Screen tags) + scripts/package-itch.py --dist dist-itch -> artifacts/Gridbound-itch-<version>.zip (+ .sha256), the itch.io HTML upload
CHROME_PATH=… npm run itch:assets  # scripts/itch-assets.mjs: redraw the itch.io store art in docs/itch/ (cover, banner, EN/ID screenshots; own Vite server on 5187)
```

There is no linter/formatter configured; `tsc` (strict) via `npm run build` is the type check.

CI (`.github/workflows/ci.yml`) runs: `npm test`, `npm run database` then **`git diff --exit-code -- data/database.json`**, `npm run build`, `npm run balance`, `scripts/package-hostinger.py`, then the itch-mode build `npx vite build --mode itch --outDir dist-itch` and `scripts/package-itch.py --dist dist-itch` (both ZIPs are uploaded as workflow artifacts; `gridbound-static` stays the web `dist/`). So any change to content definitions in `src/game/` (skills, jobs, gear, talents, quests, enemies, campaign, boons) must be followed by `npm run database` and committing the regenerated `data/database.json`. `npm run balance` fails CI unless the expert and casual scripted players (casual may retry a chapter once) clear all chapters, a novice (input every 1.5 s, 30% dodge/Guard, on the casual player's chapter-start profile) clears at least 70% of chapters with one retry, the expert wins every raid it tries, and an idle player cannot clear Act I (neither from a fresh profile nor, chapter by chapter, on the casual player's chapter-start party: `idleChapter`) — so combat/number changes can fail CI there. `raidTiers` in `artifacts/balance.json` reports what each contract tier costs (expert median end HP/potions; casual Silver/Gold win rate and median end HP) — `RAID_TIER_SCALE` Silver/Gold damage is set so the expert still wins every Gold raid while a casual player loses some. The scripted players shop and deploy like real ones (harness v2 in `scripts/balance.ts`, shared by `calibrate.ts`/`power-curve.ts`): `shop(p, run)` promotes first and equips the job skill as the stance (a non-healing job skill never replaces the last healer's heal), tier-2 branches rotate per run (`branchOf`; the expert is `RUNS.expert`, the casual/novice `RUNS.casual`, so both branches of every class are fielded), `coverageParty` deploys one hero per class before doubles, and the formation is by role (warriors/monks in front, so they take the claw); in `play()` a dodging hero goes to the nearest free unmarked tile (`safeTile`) and walks back to its formation tile once the mark has landed. Break uptime, ultimates/min, taps/s, dodges, minion hits, per-job DPS/HPS, the novice's per-chapter win rate, the idle player's result per chapter on the casual party (Act III still has an idle win), Undercroft wipe rate/guardian entry HP per depth and Roguelike floors 1-9 are reported (informational) in `artifacts/balance.json`. Raids in the harness are built exactly like `main.ts` `boot()` (`raidBattle`: whole roster + story loadouts + `defaultRaidBuild` + an authored contract, floor = cleared + 1): every enemy at Bronze, every archetype at Silver/Gold, each certified pact combo, a 6-hero party, and Bronze raids after chapters 2/6/10 (casual win rate is informational). Hero growth comes from levels (`LEVEL_POWER`/`LEVEL_HP` in `levels.ts`), gear, talents and jobs; `profileModifiers` is neutral. Enemy strength per chapter is `CHAPTER_HP`/`CHAPTER_DMG` in `simulation.ts` (raids reuse the chapter curve, scaled by `RAID_HP`/`RAID_DMG`, `RAID_PARTY_DMG` for parties smaller than the story cap, and `RAID_TIER_SCALE` per contract tier); after changing hero or enemy numbers, run `npm run calibrate` (≈5 min), paste the tables it prints as they are (the casual margin is built in: at most one loss in twelve runs, median end HP ≥ 50%, then −5% damage; the novice target is ~50% wins at chapter 1 rising to ~60% at 16; damage stays at or above each chapter's idle floor, the least damage at which an idle player loses it on both branch mixes, unless idle wins even at the casual cap; from chapter 6 on each chapter's damage is within ±20% of the previous one (chapters 2–5 may rise further, never fall more than 20%), boss HP never falls, HP ≤ ±20% inside an act — `tests/scaling.test.ts` checks the shape), then `npm run power-curve` (paste `RECOMMENDED_POWER`, a running max so it never falls, and `HEROIC_POWER_FACTOR`), `DUNGEON=1 npm run calibrate` if the Undercroft should follow, and re-run `npm run balance`.

## Architecture

- **Pure game logic in `src/game/`, no DOM.** Everything here is importable from Node tests and scripts. `simulation.ts` holds the `Battle` class: a seeded, deterministic, fixed-timestep combat simulation (`tick(dt)`, `tap`, `move`, `act`, `potion`, `ultimate`, `snapshot()`), parameterized by mode (`adventure`/`raid`/`endless`…) and `BattleOptions` (roster, loadouts, boons, rogue/raid builds, raid contracts). Tests advance it with `b.tick(1/60)` loops; determinism (`seeded encounter behavior is reproducible`) is a tested invariant — don't introduce `Math.random`/wall-clock into it. Combat rules: only casts outside `SUPPORT_KINDS` are offensive (precision, echoes, Second Thunder and leech count `offensiveActs`); delay/stun/Frost/job intent delay go through `delayIntent`, a per-intent-cycle budget (`CONTROL_MIN`/`CONTROL_SHARE`, reset in `telegraph()`); overlapping regen/Battle Hymn keep the stronger effect; curses are per hexer (`curses`, exposed in `snapshot()`); `heal(target, amount, source)` takes the healer so the healer's perk applies; nobody is downed once the boss has fallen (a counter/thorn kill on the hit that would down the last hero leaves that hero at 1 HP), and a same-frame boss death beats a wipe. Party tools are scale-invariant: a potion heals `POTION_HEAL` (28%) of each hero's max HP, Ninefold Dawn deals `ULT_BASE` + `ULT_DAMAGE` × boss max HP and heals/shields `ULT_HEAL`/`ULT_SHIELD` of max HP, Mending Light's party heal is 20 × `skillPower`, and resolve from damage is a share of `resolveRef` (the chapter's final-boss HP in Story/Undercroft, the boss itself in raids/Roguelike; `RESOLVE_DEALT`/`RESOLVE_MINION`) or of the party's total max HP (`RESOLVE_TAKEN`). Late fights keep their threats: `staggerThreshold()` is `STAGGER_SHARE` of the boss's max HP capped by `STAGGER_CAP` × `STAGGER_CAP_GROWTH`^(chapter−1), a break lasts `BREAK_SECONDS`, and minions strike `MINION_FIRST` s after spawning with `MINION_HP` × the chapter boss's HP. The story party is capped at 8 (`storyPartyCap`), so one tile is always free; Roguelike floors 1–`ENDLESS_EARLY_FLOORS` hit `ENDLESS_EARLY_DMG` harder (fading over the next three floors).
- **Content definitions** are plain TS data: `content.ts` (`KITS` basic jobs/skills, `ROSTER`), `jobs.ts` (advanced/third jobs, `GEAR`, sets), `talents.ts`, `levels.ts`, `quests.ts`, `world.ts` (`CAMPAIGN`, `ENEMIES`, `BOONS`), `story.ts`/`narrative.ts`/`characters.ts`, `d8-content.ts`. Every stage has a `beat` (the pre-wave story line); a beat that names an enemy must name that stage's archetype (`tests/story-beats.test.ts`, EN names and nicknames like 'Cantor'/'scavengers') — rewrite beats, never reorder enemy lists. `StageDef.enemyName`/`enemyTitle` rename a stage's enemy (Vharok's ally chapters 8/12/16 show what rides him) and `prepareStage` uses them; `variantName` builds 'Ashbound Last Watch' (no 'The', no double Frost). `STORY_CHOICES` (`narrative.ts`) open once chapters 0..chapter−1 are cleared (`choiceOpen`/`pendingChoices`); a choice's `line` is a sentence of the final outro that an option's `line` replaces (`storyOutro`, used by the result screen, Journal and finale); `epilogue()` returns only the choice outcomes (the lead line is the UI key `journal.epilogue.lead`); `CHARACTERS[id].fateLine` is each hero's finale line. `data/database.json` and `Gridbound_GDD_GRID_RAID.md` are generated exports of these — never hand-edit them. Tier-3 job perks are data too (`Job.perk` in `jobs.ts`: `barrier`/`echo`/`intentDelay`/`castLeech`/`minionHeal`/`overhealBarrier`) read by `Battle` — don't key combat rules on job ids; `tests/job-perks.test.ts` checks that every tier-3 perk fires and that job and AoE skill texts state the runtime numbers.
- **Two save layers:**
  - Legacy `Profile` (`profile.ts`, `save.ts`) in `localStorage` key `gridbound.v3`, with v1/v2 migration; malformed saves disable writes instead of overwriting. Progression mutations (`promote`, `equipGear`, `buyTalent`, `settleProgress`, `completeZone`, `claimQuest`, …) are functions over a `Profile`. `gridbound.v3` is now only the migration source: at boot `ensureCommander()` (main.ts) activates the latest Commander or, when there is none and the legacy save is writable, runs `backupLegacy` (raw copy to `gridbound.v3.backup-<ISO>`, newest 3 kept) and creates a Commander from the live profile (`migrateLegacy`/`adoptCommander`, bank included; the list→create step runs under the Web Lock `gridbound.commander-migration`, so tabs that boot together migrate once). ## Conventions

- Match the existing dense style: much of `src/game/` and the tests are compact one-line functions/tests with minimal whitespace. Imports use extensionless relative paths.
- Never hard-code player-visible strings in UI code; add a key to both `en.ts` and `id.ts`. Source strings authored inside `src/game/` are mostly Indonesian prose with English names; their translations live in `src/i18n/content-text.ts`.
