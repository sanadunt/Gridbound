# GUI acceptance targets

This document records requested targets, not test results.

- Separate training overview, active skills, jobs, talent branches, equipment and formation. Do not hide required content to claim no scrolling.
- Paginate long quest, chapter, enemy and equipment collections. Preserve all records and navigation.
- Forest green surfaces, brass action accents and existing local pixel art retain Gridbound's identity. Each screen focuses on one decision. Energy 2, rhythm 2, motion 2.
- Prerequisite arrows communicate actual talent dependencies, including combined prerequisites. They are not decorative button arrows.
- Equipment inspection must be free: show description, requirements, stats and comparison before explicit purchase/equip confirmation.
- Victory presents a finite enemy death sequence before result choices appear. Choices reject mouse, touch and keyboard activation for a full second after appearing.
- Old animation/timer callbacks must not reopen or unlock a replacement screen.
- Test desktop and mobile document bounds, visible content, pagination, save preservation and production hosting. Report any remaining vertical overflow honestly.
- No push or deployment is authorized by this GUI implementation task.
